# JSONL 导入场景与性能记录

记录日期：2026-09-12。以下均为仓库脚本在本机实际执行的结果。输入由脚本确定性生成，
属于模拟导入数据，不冒充生产数据或真实用户案例。

## 场景目标与验收边界

场景：导入包含合法 JSON、可修复宽松 JSON、缺值、重复键及超长记录的事件 JSONL。

验收条件：

1. 2,000 条物理记录必须产生 2,000 条结果，不静默丢行或合并行；
2. 每条成功结果必须能被 Node.js `JSON.parse` 接受；
3. 每条成功修复必须能以原始 UTF-16 编辑记录回放得到相同输出；
4. 无编辑的合法 JSON 必须逐字保留；
5. 缺值、重复键和超长行必须明确拒绝；超过 1 MiB 的行跨越多个 64 KiB 读取块；
6. 超长行之后的记录仍须被处理；汇总数字必须和逐行结果一致。

复现命令：

```sh
moon build --target js --deny-warn
node scripts/test-import-scenario.mjs
```

本次结果：输入 2,000 条、1.08 MiB，用时 156.8 ms；1,960 条接收，其中 1,306 条
修复、654 条保持原文；40 条拒绝；共记录 6,530 项编辑。脚本完成全部断言后才输出结果。
该时间为一次本机观测值，不是跨机器性能承诺。

## 吞吐复现

```sh
node scripts/benchmark-jsonl.mjs
```

环境：Windows 11 10.0.26100、Intel Core i7-14650HX（24 逻辑处理器）、15.6 GiB RAM、
Node.js 24.13.1、MoonBit 0.1.20260904、moonc v0.10.12（2026-09-07）。

| 记录数 | 输入大小 | 用时 | 记录/秒 | 输入 MiB/秒 |
| ---: | ---: | ---: | ---: | ---: |
| 1,000 | 0.05 MiB | 118.0 ms | 8,476 | 0.40 |
| 10,000 | 0.48 MiB | 336.5 ms | 29,720 | 1.41 |
| 50,000 | 2.42 MiB | 1,038.3 ms | 48,158 | 2.33 |

数字包含 Node 子进程启动、逐行 JSON 报告生成以及测试脚本捕获全部 stdout 的开销，
不是跨机器性能承诺。当前没有可靠的跨平台峰值内存采样，因此不声明峰值内存数字。
核心增量处理器只保留当前未完成行，默认单行上限为 1,048,576 个 UTF-16 码元；
测试脚本自身会缓存输入与输出。

## 已验证与未验证

已验证：64 KiB 分块读取、跨块行拼接、UTF-8 增量解码、逐行守恒、失败隔离、编辑回放、
合法输入原文保持、汇总一致性及超长行后的继续处理。

未验证：生产数据、网络流、并行输入、持续数小时运行、不同 Node/MoonBit 版本的性能稳定性，
以及业务 Schema 正确性。修复成功只代表输出为合法 JSON，调用方仍须执行 Schema 和权限校验。
