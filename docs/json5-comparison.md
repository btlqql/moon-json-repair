# JSON5 重叠与可验证差异

核对日期：2026-09-11。本文件回应初审的生态重叠意见，不宣称已获得认可。
官方尚未提供具体对照项目；这里主动对照现有的 `tiye/json5@0.0.3`。

## 承认重叠

[tiye/json5](https://github.com/worktools/json5.mbt) 是现有 MoonBit JSON5 解析/序列化库，
采用 Apache-2.0。其[包文档](https://mooncakes.io/docs/tiye/json5@0.0.3)列出了裸键、单引号、
注释、尾逗号和 core Json 转换。这与本项目的主要输入类型直接重叠，不能把这些语法支持
本身当作新贡献。此前来源说明漏列该项目，现已补充。

## 比较范围

以下 tiye/json5 一栏仅依据上述公开 API/文档，不是独立运行它得到的测试结论。
“未列出接口”不意味着其他工具不能实现，也不证明本项目值得重复建设。

| 需求 | tiye/json5 公开契约 | Moon JSON Repair 已实现的契约 |
| --- | --- | --- |
| 宽松 JSON 输入 | 接受上述 JSON5 语法，解析为值树 | 接受其中一部分并输出标准 JSON 文本，存在重叠 |
| 返回原始修改位置 | API 列表以 parse/stringify 和值转换为主，未列出编辑日志接口 | 返回原始 UTF-16 半开区间、替换文本、原因码 |
| 校验修复过程 | 未列出原始文本编辑回放接口 | apply_edits 校验位置、重叠及代理对边界，可重建输出 |
| 保持原文 | 文档描述解析/重新序列化，未承诺原文逐字符往返 | 合法输入保持原文；修复时保持未修改切片和数字拼写 |
| 语法覆盖 | 包括十六进制数、Infinity、NaN | 不接受这些扩展，不以更广的语法覆盖为目标 |

本库也拒绝重复键、缺失值，支持显式启用的容器闭合和 JSONL 诊断。但没有对照测试时，
不能把“拒绝错误输入”说成独有能力，也不能推断 JSON5 库的重复键行为。

## 可运行证据（本项目）

在仓库根目录执行：

```sh
moon run examples/audit --target js
moon test --target js --deny-warn
```

示例输入：`{id:9007199254740993, n:1.2300e+02, label:'Moon',}`。
输出：`{"id":9007199254740993, "n":1.2300e+02, "label":"Moon"}`。
数字拼写保持不变；打印的编辑记录使用原始输入坐标。
输出还包括 `Replay equals output: true`、`Strict recheck edits: 0`，
以及重复键案例的 `Refusal: DUPLICATE_KEY at 15`。

[audit_contract_test.mbt](../audit_contract_test.mbt)增加三项独立契约检查：

1. 合法 JSON 的空白/大整数/指数拼写保留，以及修复时数字不重写。
2. 带非 BMP 字符、注释、单引号、尾逗号的混合编辑可回放。
3. 重复键产生包含位置的明确拒绝，而不是选取某个值。

## 适用性及需要主办方判断的部分

若调用方只想读取带注释的配置，现有 JSON5 解析库很可能已满足需求。
本项目面向另外一种契约：预览源文本修改、保留未修改内容，并允许调用方回放核对。
它不验证模型意图，不做业务 Schema/权限校验；回放一致也不证明业务数据正确。

这些已有能力是否足以满足比赛新增价值要求，需主办方判断。
本次补充的是证据与测试，没有将已有能力包装成本期新实现的功能。
